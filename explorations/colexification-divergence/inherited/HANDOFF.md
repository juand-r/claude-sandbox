# Handoff Document

## Project status as of 2 August 2026

### What is done

1. **CLICS4 analysis complete.** We cloned the CLICS4 repo, inspected the source
   code, and established exactly how colexification detection works (phonological
   matching on the Segments column, not orthographic). We extracted
   colexification asymmetries for English-Spanish and mapped the top global
   concept pairs to major NLP languages.

2. **Test dataset built.** 20 naturally occurring sentences across three language
   pairs (Russian-English, Spanish-English, Japanese-English) and three concept
   pairs (LEG/FOOT, WOMAN/WIFE, HEAR/LISTEN). Each sentence is annotated with
   the degree of contextual disambiguation.

3. **LLM test script ready.** `src/test_haiku.py` calls Claude Haiku 5 times per
   sentence and records which English word it picks. Needs an API key to run.

4. **PDF report generated.** Summarises the motivation, method, and findings.

### What is not done

1. **The LLM test has not been run.** No API key was available in the sandbox
   environment.

2. **Corpus-scale collection.** The 20 test sentences were hand-collected from
   web search results (Reverso Context, Linguee, Cornell Russian Lexical
   Database). A larger-scale collection from OpenSubtitles, Tatoeba, or literary
   translations would give more statistical power.

3. **Beyond three pairs.** We analysed only LEG/FOOT, WOMAN/WIFE, HEAR/LISTEN.
   Other promising pairs from the CLICS4 data include:
   - FLESH/MEAT (English is the outlier; 105 families colexify)
   - DO/MAKE (English distinguishes; most others collapse)
   - WOOD/TREE (Japanese, Polish, Turkish colexify)
   - SKIN/BARK (53 families colexify)
   - BLUE/GREEN (the classic; 70 families)
   - MOUNTAIN/HILL (84 families)

4. **Non-English-centric pairs.** All current tests use English as the target
   language. Interesting pairs exist between, say, Russian and Japanese (both
   colexify LEG/FOOT but Russian distinguishes HEAR/LISTEN while Japanese does
   not).

5. **Connection back to X-PARADE.** The forced divergence examples have not been
   annotated in X-PARADE format. The claim that these represent a distinct,
   structurally motivated category of information divergence remains to be
   validated against the X-PARADE taxonomy.

6. **The homophone filter.** We identified that CLICS detects some English
   "colexifications" that are really homophones (sea/see, meat/meet, right/write).
   These can be filtered by checking whether Segments match but Form differs. The
   filter is straightforward to implement but has not been applied to the data
   yet.

### Decisions to make

1. **Scale of the test set.** The current 20 sentences are a proof of concept.
   A publishable study would want hundreds, ideally sampled from a parallel
   corpus rather than hand-picked. The question is whether to invest in
   downloading and processing OpenSubtitles (large, noisy, everyday language)
   or Tatoeba (smaller, cleaner, community-curated).

2. **Which LLMs to test.** The script currently uses Claude Haiku. Extending to
   GPT-4o, Llama, Mistral, etc. would show whether the inconsistency pattern is
   model-specific or general.

3. **What "consistency" means.** The current test checks whether the same model
   picks the same word across 5 runs of the same sentence. A stronger test would
   check whether the model's choice is consistent with its behaviour when asked
   about the content in the source language. For example: ask in Russian "does
   your noga hurt above or below the ankle?" and in English "does your [leg/foot]
   hurt?" and check whether the answers are compatible.

4. **Paper framing.** This could be framed as:
   (a) a contribution to X-PARADE (extending the divergence taxonomy to include
       structurally forced divergences),
   (b) a contribution to multilingual LLM evaluation (using CLICS to generate
       targeted consistency tests), or
   (c) a contribution to computational typology (using LLMs to probe whether
       colexification patterns are reflected in model representations).
   These are not mutually exclusive but the emphasis affects what experiments to
   prioritise.

### Things I got wrong during the investigation

For the record, since accuracy matters:

1. I initially said CLICS matches on the Form column (orthographic). Wrong: it
   matches on Segments (phonological).
2. I initially said CLICS doesn't track which transcription convention is used.
   Partially wrong: the CLDF format supports this at the dataset level via
   dc:conformsTo, but the CLICS4 metadata does not set this property.
3. I initially said CLICS doesn't store per-language edge data. Wrong: the
   colexifications.csv carries full lists of languages, varieties, and families
   per edge.

All three were corrected after checking the data and source code.
