# Theory: obstacles to non-CTS computation in Rule 110, and the best target

Author: scholar. Status labels: **[thm]** a proved result from the
literature (cited); **[sim]** checked by simulation here or independently
by two teammates; **[arg]** an argument of mine, not a proof; **[hyp]** a
hypothesis to test.

The literature behind this document is in `SURVEY.md`.

---

## 1. The main claim

Rule 110's glider physics has a *transport asymmetry*: stationary stored
data (C gliders) can be crossed by some left-moving gliders but by no
right-moving glider, and data moving with the left-going stream (Ebar
gliders) can be crossed by some right-movers but by no faster left-mover.
With one program stream arriving from the right, the only store that can
report back to the program is the one nearest to the stream. A single store
that is written at one end and read at the other is a queue, and a queue
driven by a periodic program is a tag system. **This is, I argue, why
Cook's construction is a cyclic tag system, and it tells us exactly what a
non-CTS machine must add: a way to carry information rightward across a
stored cell (a relay), or a single-store machine that is a queue with a
genuine finite control.**

The argument has four steps: the model (section 2), the crossing table
(section 3), the access geometry (section 4), and what it leaves open
(sections 5-7).

## 2. The model: Rule 110 gliders as a lattice signal machine

### 2.1 Signals

Every glider has a period vector (t, x) that is a non-negative combination
of the B period (4, -2) and the A period (3, 2) **[thm]** (NKS notes to
s.6.8; Cook 2004 Fig. 5). Hence every speed lies in [-1/2, 2/3]. The known
natural speeds are:

| direction | gliders | speed |
|---|---|---|
| right | A, and bundles of A's | 2/3 |
| right | D1, D2 | 1/5 |
| stationary | C1, C2, C3 | 0 |
| left | F | -1/9 |
| left | H | -9/46 |
| left | E_n, Ebar (and E, Ebar trains) | -4/15 |
| left | G_n | -1/3 |
| left | B, Bbar_n, Bhat_n | -1/2 |
| left (object) | glider gun | -20/77 |

### 2.2 Phase and collision classes

The ether is invariant under a lattice L of index 14 in Z^2 (generated by
(7, 0) and (3, 2)). A glider can be placed only on one coset of L, so two
gliders X, Y can meet in exactly |det(P_X, P_Y)| / 14 inequivalent ways
**[thm]** (Cook 2004 s.3.1) **[sim]** (`class_check.py`: 4 classes for C x
Ebar, 6 for A x Ebar; outcome is a function of class). The result of a
collision is fixed by its class; the only freedom a designer has is which
class (spacing mod the lattice) to use.

### 2.3 Charge

Each glider has a width w (ether offset right vs left, mod 14); the sum of
widths is conserved by every collision **[thm]** (Cook 2004 s.3.1). Widths
(my sign convention, **[sim]** `r110check.family`): A 8, B 6, Bbar 6, Bhat 3,
C1 5, C2 11, C3 3, D1 3, D2 9, E 9, Ebar 7, F 13, G 4, H 3. Any proposed
reaction can be screened with this in one line.

### 2.4 The phase-free sub-chemistry

When |det| = 14 there is one class, so the outcome cannot depend on timing.
This holds for A and B (the two "speed of light" gliders) against every C
and D, and for A x B. **[sim]** (`unique_pairs.py`; collider and architect
found the same table):

    A + C1 -> F      A + C2 -> C1     A + C3 -> C2
    A + D1 -> C2     A + D2 -> D1     A + B  -> (nothing)
    C1 + B -> C2     C2 + B -> D1     C3 + B -> E
    D1 + B -> E      D2 + B -> A + Ebar

Also single-class but not in this table: B x E (det 14). Cook's tight A4
bundle has the same period as A, so A4 x C and A4 x B are single-class too
**[sim]** (`cookA4.py` harness): A4 + C1 -> E, A4 + C2 -> A + Ebar,
A4 + C3 -> Ebar, A4 + D1 -> Ebar, A4 + D2 -> B + Ebar, A4 + B -> A^3.

This matters because it is the property that made Ollinger and Richard's
4-state intrinsically universal CA provable by pure symbolic reasoning
(their Lemma 8). Gadgets built only from single-class reactions need no
spacing arithmetic at all; gadgets that use multi-class reactions need
Cook-style invariants (spacing mod 4 or mod 6) carried through every
crossing.

### 2.5 Signal-machine theory that applies

- Two speeds: at most quadratically many collisions **[thm]** (Becker et
  al. 2013).
- Three speeds with all ratios rational: cyclic dynamics, no universality;
  four speeds suffice for universality **[thm]** (Durand-Lose 2011, 2013 as
  reported in Becker et al. 2013).
- So a Rule 110 computer grown from a *finite* seed must use at least four
  glider speeds, **if** the signal-machine abstraction transfers
  **[arg]**. With infinite periodic streams (as in Cook) the theorem's
  hypothesis fails and three speeds suffice (Cook uses A, C, Ebar).

## 3. The crossing table (who can pass whom)

"Crosses" means: some collision class leaves both gliders intact (a
soliton). Evidence: collider's catalog (718 binary collisions, verified),
my checks of 18 Martinez solitons, and the single-class table.

| moving glider | crosses stationary C? | crosses Ebar? |
|---|---|---|
| A (right) | never (single class, always reacts) **[sim]** | yes, 4 of 6 classes **[sim]** |
| tight A4 (right) | never (single class) **[sim]** | yes, 1 of 6 (Cook's invisibles) **[sim]** |
| specific 8-A packet (right) | **yes, with fuel**: C1, C2, C3 restored (displaced about -8), 7 A's absorbed, 1 A continues (synth's SAT result; verified by `check_apacket.py`) | - |
| D1, D2 (right) | never (single class) **[sim, collider/architect]** | - |
| C1, C2 (at rest) | - | yes: C1 2 of 4, C2 1 of 4 **[sim]** |
| C3 (at rest) | - | never (4 classes) **[sim]** |
| F (left, slow) | C1, C2: 1 of 2 each **[sim, collider]** | Ebar crosses F in 7 classes **[sim]** |
| Ebar (left) | C1: 2 of 4, C2: 1 of 4 **[sim]** | - |
| B (left, fast) | never (single class) **[sim]** | never (2 classes: B -> B^3 + A^2) **[sim]** |
| Bbar, Bhat (left, fast) | ? | never (6 classes each) **[sim]** |
| G (left, fast) | ? | never (6 classes: Ebar + A^4 in 5, C2 in 1) **[sim]** |

The pattern, in words:

- **Lab frame (C data at rest):** crossed by left-movers of moderate speed
  (Ebar, F), never by right-movers, never by the fastest left-movers (B).
- **Ebar frame (moving data at rest):** crossed by what moves right
  relative to it (A, C, F), never by what moves left faster than it (B,
  Bbar, Bhat, G).

In both frames, stored data is transparent from one side only for single
gliders. This is architect's observation (board, "architecture choice") and
I confirm it for single gliders and for Cook's A4. It is **not** a theorem,
and it fails for packets that pay fuel: a specific packet of 8 tightly
packed A's crosses any C and leaves one A (synth; verified). The cell eats
7 A's, one full cycle of the width charge (7 x 8 = 56 = 0 mod 14). So the
honest statement is: right-moving information can cross a stationary cell
only by paying 7 A's per cell, with a packet built to a precise internal
spacing (other 8-A trains fail, `check_apacket.py`). Synth's SAT bounds
extend the single-glider statement: no stationary object of width <= 24
lets a single A pass through as an A-train. **[sim]** I confirmed this independently: `stationary.py`
enumerates all 1260 (7,0)-invariant objects of census width <= 24 by the de
Bruijn method and hits each with an A; no outcome contains any right-moving
A-type glider.

## 4. The access geometry, and why it produces a queue [arg]

Set-up. A program must be supplied as a periodic stream (section 6.2
explains why the program has to be data). Say it arrives from the right as
left-movers, as in Cook. Stores are sequences of stationary C's. Place
stores S_1 (nearest the stream), S_2, ..., S_k further left.

1. *Commands reach every store.* A command for S_j is a left-mover that
   crosses S_1 .. S_{j-1} (possible in the right class: Ebar or F across C1,
   C2).
2. *Only S_1 can answer.* An answer must affect packets that have not yet
   arrived, i.e. it must travel right, or at least stay to the right of
   the stores the future packets hit first. An answer from S_j (j > 1) is
   born to the left of S_1 and must pass S_1 rightward. No single glider
   can do that (section 3); a fuel-paying A-packet can cross a bounded
   number of cells (7 A's per cell), which is useless for a pile store of
   unbounded size but fine for a store of bounded size (two markers).
   (An answer does not need to be a right-mover: a stationary flag or a slow
   left-mover is also met by every later packet. But such a flag, born at
   S_j, is still to the left of S_1, so packets meant for S_1 reach S_1
   before they see it.)
3. *A second stream helps only at the back.* A periodic stream from the
   left (Cook's ossifiers) can act on the far-left end of the store region.
   So the one store that can talk to the program is read at its right end
   (by the program stream) and written at its left end (by converting
   crossing data with the left stream). A store with that access pattern is
   a **queue**.
4. *A queue plus a periodic program is a tag system.* If the program is a
   fixed cycle of appendants and the read decides only accept/reject, the
   machine is a CTS. If the read can also change which appendants are
   eligible next (a finite control), it is a Post (queue) machine or a
   clockwise Turing machine; still a queue, but not a CTS.

So under the present physics, the natural machines are queue machines,
and Cook found the simplest one. Every non-CTS design must break one of the
premises:

- **(R) Relay:** a multi-glider mechanism that carries a right-moving signal
  across a stored cell and leaves the cell's value intact ("store and
  forward", driven by the stream). Then k stores can answer, and two
  counters or a Turing tape become possible.
- **(Q) Queue with finite control:** keep one store, but make the program
  stream carry states and branch (skip) on the read. This is a clockwise TM
  or Post machine realised directly, without the CTS encoding.
- **(F) A different frame for a second store.** Data at rest in the Ebar
  frame is transparent to right-movers. But such data moves left with the
  stream and must be regenerated; in Cook's machine exactly this cycle
  (moving data -> tape data -> read -> moving data) is the queue. I do not
  see how to get a second independent store this way. **[arg]**
- **(D) Distance registers.** Store a counter as the distance between two
  markers instead of a pile of cells. A relay then only has to cross two
  markers, not a pile. Displacement primitives exist: crossing an Ebar
  shifts a C2 by +7 cells (collider), and A-then-B turns C2 -> C1 -> C2
  displaced by -4 cells **[sim, collider; my run shows the same
  C1 -> C2 -> C1 cycle with a net displacement]**. A zero test would be a
  reaction that differs when the two markers are adjacent.

### 4.1 The obstruction is frame-dependent: drifting stores [arg]

Credit: architect found this first (BOARD 05:40, "F memory breaks the
one-way obstruction"); I derived it independently later and add only the
general criterion below.

The argument above assumed stationary stores. Redo it with stores that move
at speed v_s, a program stream at speed v_p (from the right) and answers at
speed v_a. For every store to be commandable and every answer to become
effective, it suffices that:

1. v_p < v_s, and program packets cross stores (to reach deep stores);
2. v_s < v_a, and answers cross stores (the stores overtake the answer, so
   after a delay every answer lies upstream, i.e. to the right, of every
   store); and
3. v_p < v_a, and program packets react with answers (so answers can edit
   the program, e.g. delete the next k packets).

With stationary C stores (v_s = 0) condition 2 needs a right-moving answer
that crosses a C, which does not exist (F6). But the crossing table allows
another assignment:

| role | glider | speed | required crossing | available? |
|---|---|---|---|---|
| program packets | Ebar trains | -4/15 | Ebar crosses F | 7 of 12 classes (collider; Martinez solitons) |
| stores | F clusters | -1/9 | F crosses C1, C2 | 1 of 2 classes each (collider; Martinez) |
| answers | C1, C2 | 0 | Ebar reacts with C | 3 non-crossing classes of 4 for C2 |

So "drifting stores" (data in F gliders, moving left at 1/9) with stationary
answers and an Ebar program stream satisfy all three geometric conditions.
The price is a latency: an answer becomes effective only after all shallower
stores have drifted past it, so the program needs idle packets. What is
still missing is the store chemistry itself: INC, DEC and zero test on
F-based stores by Ebar packets, packet addressing (a packet must cross the
F's of shallower stores and react with the F's of its target store; with 12
classes, "address = class" as in Cook's moving data versus invisibles is
plausible), and answer creation. Relevant catalog entries: C2 + Ebar ->
C1 + F (creates an F), A + C1 -> F (creates an F, single class), F + Ebar in
5 reactive classes (destroys an F: B, B^2 + A, G + A^2, ...).

This is a hypothesis about architecture, not a construction. Its value is
that it replaces the relay (a search with no hits so far) by requirements
that are all satisfied at the level of binary collisions.

**The main hazard: data-dependent phase drift.** Every clean crossing
displaces both partners by a fixed vector. A packet addressed to store j
crosses all F's of stores 1..j-1, and their number depends on the data
(counter values). The packet's collision class at store j is its relative
position modulo the lattice <P_Ebar, P_F> (12 classes), so it shifts by
k * d (mod that lattice) after k crossings. Unless d has order dividing
every possible k, the class at the target store depends on the data, and
the command misfires. Cook met exactly this problem and solved it with a
balanced code: appendant lengths must be multiples of 6 "so that the
leader after a rejected appendant will hit the next symbol of tape data
correctly" (Cook 2009 p.38). The same remedy applies here: choose the
unary unit (the number of F's per counter increment) as a multiple of the
order of the crossing displacement in the relevant class group, or use
codes whose total displacement is data-independent (architect's "balanced
codes"). This order is computable from collider's displacement table
before any simulation.

### 4.2 Order independence: the three-family "Yang-Baxter" condition

Architect's result (board, "order-independent wiring layer"): when three
families that pairwise cross (messenger C1, memory F, stream Ebar) meet in a
data-dependent order, pairwise cleanness is not enough, because each
crossing displaces both partners and so changes the class of later
meetings. Requiring each meeting to have the same class in both possible
event orders (a Yang-Baxter-type condition, familiar from factorized
scattering of solitons) selects a unique triple of classes: C1 x F class 1,
F x Ebar class 3, C1 x Ebar class 1. This is the three-family version of
Cook 2004 fig. 5(d) ("all of the Ebars will cross all of the C2s"), where
the same argument is made for two families. In Ollinger-Richard terms it is
a statement that a catenation scheme's valid affectations do not depend on
the order of the crossings. **[sim, architect; confirmed by me]**:
`check_yb2.py` evolves architect's placements with `engine.step` and types
the result with my own census typer: 10/10 clean over the messenger's
entry shifts, while the pairwise-clean control triple (C2 x F#1,
F x Ebar#8, C2 x Ebar#2) breaks in every run.

A hazard follows from the same displacement algebra **[arg]**: used
messengers are lane gliders nobody consumes, so every later packet crosses
a data-dependent number of them. Inside the lane that is harmless, but
relative to any non-lane object (a lock or register head) the packet's
class drifts with the history, unless messengers are consumed after use or
the non-lane objects cross the same messengers.

### 4.3 Counting needs reactions; a counter can live in one glider

*No winding (architect, board).* For a register made of two markers and
changed only by clean crossings, the change of the gap is a function of a
finite residue (the markers' relative position modulo the collision
lattices), and a breadth-first search over all residues and clean classes
finds no cycle with nonzero net change. So crossing-only registers store a
bounded amount (one bit for a C1 pair), never an unbounded count. My own
observation that one Ebar can move two C1 markers by +6, 0 or -6
(`dist_register.py`) is consistent with this: it is the 1-bit residue, not a
counter; my `transducer.py` re-derives the same structure independently
(all 16 residue-class entries are functions; two residues, moves +6, -6,
idle). **[sim, architect; confirmed by me]**

*Multi-body packets do count (architect, correcting the above).* Tight
Ebar pairs act on an F differently from two independent Ebars, and with
them the gap between two F's does wind: three-packet sequences give INC and
DEC of a two-F register by a fixed lattice vector, returning the phase
residue, so the same packets work at every value, with nothing created or
destroyed. **[sim, architect; confirmed by me]** `check_xcounter.py`
evolves architect's schedules with `engine.step` and checks both F's
cell-exact with ether context: INC^k DEC^k for k = 1, 4, 6 and mixed
strings pass; a control with one packet shifted by (3,2) fails. Scope:
each packet is placed relative to the front marker's current position (a
history-aware schedule), not yet a fixed periodic stream.

So the correct statement is: single-glider crossings cannot count;
multi-body crossings can; reactions (unit creation and destruction) can.

*The E_n counter.* Cook's extendible glider E_n (period (15,-4) for every
n) is a reaction-based unit store (collider verified it end to end as well). **[sim]** (inline runs, `ecount.py`):

- INC: B + E_n -> E_{n+1}. B x E has |det| = 14, a single class, so the
  increment is timing-free. The width grows by 6 per B (B's own width), and
  the glider by 3-4 cells.
- DEC: A + E_n has 3 classes; in some of them A + E_n -> E_{n-1}
  (E_2 -> E_1 in every sampled class; for n = 3..5 one class decrements and
  another gives Ebar-based debris).
- Zero test: A + E_1 -> C3 or D1, never an E. C3 + B -> E (single class)
  re-creates a zero counter from the answer.

Access geometry: B's (INC) and G's (DEC, class-free, answer A^3 goes back
right) both reach E_n from the right, so a single E_n is a complete
one-sided counter for a program stream arriving from the right (collider's
observation). A's reach it only from the left (DEC in one class). Two such
counters still need addressing, because neither B nor G passes an E_n; an
E_n moves with the Ebar stream (same speed), so it can travel inside the
program stream.

## 5. Which abstract model fits glider dynamics most directly

1. **Signal machines** are the exact abstraction (Cook's "glider systems"
   are signal machines on a lattice with phases). Universality of signal
   machines is known via CTS, 2-counter machines and TMs (Durand-Lose).
2. Among universal models, the fit depends on the store geometry above:
   - *Queue machines (tag systems, CTS, Post machines, clockwise TMs):*
     native to the geometry; Cook's route.
   - *Counter machines:* the most economical non-queue model (a store per
     counter, three operations: INC, DEC, zero test). Needs relay (R) or
     distance registers with a relay across markers (D).
   - *TM with a head particle (Lindgren-Nordahl):* no store crossing is
     needed (the head only meets its neighbours), but every transition is a
     separate head-cell reaction, all of which must be found; the reaction
     set grows with the program unless one fixed small universal machine is
     used, and the head must reflect off stored cells, which the
     right-mover chemistry does not offer cleanly (no right-mover survives
     meeting a C).
   - *Circuits:* 1-D circuits need signal crossing and fan-out in both
     directions; they inherit the same asymmetry and in addition need a
     one-to-two splitter.
3. **Recommendation.** Target: the cyclic skip machine of section 6.6 (a
   Minsky two-counter machine whose program is a periodic stream from the
   right, with two-length conditional skips). It is the smallest non-queue
   universal model with a program-independent reaction set. Two physical
   routes, in order of promise: (i) architect's F-memory (drifting stores,
   section 4.1), whose requirements already hold pairwise; (ii) distance
   registers in the lab frame with A-packet answers that pay 7 A's per
   marker crossed (needs a packet that survives more than one crossing).
   Safe fallback that is still not a CTS: (Q), a queue machine with a real
   finite control, i.e. a clockwise TM realised directly from Cook-like
   parts.

### 5.4 Option (Q) in detail: a queue machine with a real finite control [arg]

This option keeps Cook's store (tape data read by leaders from the right,
written by ossifiers from the left) and changes only the control.

What a CTS cannot do. In Cook's machine every leader reads exactly one tape
symbol, and the acceptor or rejector it makes is absorbed by the next
leader: "the rejector ... eliminate[s] each symbol of table data, until
eventually it hits the next leader, which absorbs it" (Cook 2004 s.2.3).
The accept/reject decision therefore never outlives one appendant. The only
control state is the position in the appendant cycle. This is the
"geometry problem" of Cook 2009 p.32 that forces unary encodings.

What a Post machine (queue automaton) needs. States q, queue alphabet
{Y, N}, transitions delta(q, s) = (q', w). Program stream = one block per
state; block q = [read leader][w(q,Y)][w(q,N)][jump to block q'(s)]. The
read decides which of the two appendants is kept (accept one, reject the
other), and then the stream must discard blocks until block q'(s).

New reaction types needed, all in Cook's family "A-material from the left x
Ebar-material from the right", so all subject to Cook's mod-6 bookkeeping:

1. **Relay leader** (does not read tape): acceptor + relay leader ->
   rejector, and rejector + relay leader -> acceptor (so the decision is
   inverted across the boundary between w(q,Y) and w(q,N)), or any variant
   in which the outcome depends on which of the two hit it.
2. **Skip leader**: rejector + skip leader -> rejector (the rejection
   continues through the next block), acceptor + skip leader -> absorbed or
   converted, so that "delete everything up to the next hard leader"
   implements a jump. Jump targets are encoded as the number of soft
   leaders before the next hard one.
3. Everything else is Cook's: ossification, crossing, tape read.

Why this is worth considering.

- It is not a CTS: the machine is a queue automaton with an arbitrary finite
  control. (A skeptic may call it "CTS plus control"; the lead should decide
  whether that meets the goal.)
- It removes the unary encoding. Clockwise Turing machines map to Post
  machines directly (Neary-Woods), so the parent project's dominant cost,
  2|Phi| CTS reads per tag step and the |Phi|^3 law of REPORT.md s.4, would
  drop out. This is a concrete engineering benefit, independent of the
  research question.
- The needed reactions are few (two leader types) and program-independent.
- Risk: Cook's leader internals are not documented ("Only the inner
  workings of the components and leaders were treated as given without
  analysis", Cook 2009 p.39), so new leaders must be found by search in the
  A-material x Ebar-material family. Synth's tools fit this well.

## 6. Other obstacles, each with its status

### 6.1 Fuel [thm + sim]

Rule 110 is not reversible, and every non-crossing collision destroys
information. Cook's construction consumes the table and the ossifiers
(Richard 2008: it "does only erase particles"). An unbounded computation
therefore needs an unbounded supply of gliders. Two sources exist:
ultimately periodic initial conditions (infinite streams, standard for
Turing universality of CA) and glider guns. **[sim]** The gun moves at
(77, -20) and emits one A per period to the right, about 71 cells apart. A
gun's output is periodic, so it can supply clock or fuel, not program.

### 6.2 The program must be data [arg]

A CA has a fixed finite set of collision types. A machine whose transitions
are separate reactions (a TM head colliding with each symbol) needs one
reaction per transition, so either the design is re-searched for every
program, or one fixed universal machine is compiled once. Cook avoids both
by making the program a stream of identical parts arranged in different
spacings (table data), so that a fixed set of five reaction families runs
any program. A non-CTS design should do the same: a small fixed reaction
set, program as spacing-encoded stream.

### 6.3 Crossing [thm]

Opposite-moving data must cross. Cook's solution (2004 s.3.2.3): encode
data in spacings between identical gliders and use one crossing collision
whose displacement is the same for every glider, so spacings survive. The
crossing table in section 3 lists the available soliton classes.

### 6.4 Timing [thm + sim]

Multi-class collisions are correct only in the right class; Cook tracks this
with "over distance" mod 4 (C2 x Ebar) and "up distance" mod 6 (A x Ebar).
Crossings displace both gliders by fixed amounts, so each crossing shifts
the class arithmetic by a known constant; Cook's appendant-length-multiple-
of-6 rule is the consequence. Designs based on the single-class chemistry
avoid this entirely.

### 6.5 Speed count [thm, transfer is arg]

See 2.5: finite seeds need four speeds under the signal-machine
abstraction.

### 6.6 The exact abstract target: a cyclic skip machine [sim]

To make "Minsky machine with the program in the stream" precise, I define
and test the machine the gliders would have to implement (`csm.py`).

- Two counters. The program is a cyclic list of packets, supplied
  periodically. After a packet executes, the next s packets may be deleted
  ("skip s"); execution continues with the first packet not deleted.
- Packets: `INC r`; `DEC r (s_zero, s_pos)`: if r = 0 skip s_zero, else
  decrement and skip s_pos; `NOP`; `HALT`.
- Compiler from any Minsky machine: one block per instruction; targets
  become forward skip counts mod the program length (backward jumps wrap
  around the cycle). An unconditional jump is `INC r0; DEC r0 (-, s)`: the
  positive branch is certain and r0 is restored, so **no third register is
  needed**. A DEC answer that arrives late is modelled by `latency` NOP
  packets after each DEC; the compiler inserts them, and skip counts include
  them.
- Test: 1212 differential runs (hand-written programs and 400 random
  Minsky programs, latencies 0, 1, 3) against a direct Minsky interpreter;
  halting and final registers agree in all runs.

Consequence for the glider design (**a gap in ARCHITECTURE.md s.3.1 as
written**): with the DEC answer "if zero skip k, otherwise skip 0" alone,
INC instructions and nonzero branches can only fall through, so under
direct compilation the fall-through successors must form one cycle through
the whole program. A loop body followed by a backward jump then drags
execution through every other instruction of the program. I do not see how
to compile general programs that way. It becomes immediate if either (a)
the DEC answer carries a skip on the nonzero branch too (two skip lengths
per DEC packet), or (b) an always-zero register provides unconditional
skips (Minsky's scratch register is zero only between macro-steps, not
inside loops, so it does not suffice by itself). Option (a) is the cheaper
one: the answer mechanism must delete a program-given number of packets in
either case.

## 7. Reactions the recommended target needs

Two-counter machine, program periodic from the right, stores as piles or
as marker pairs. Notation: P = a stream packet (left-mover, Ebar-based so
it can cross C's); S = a stationary cell (C1 or C2).

## 8. What would change my mind

- A right-mover crossing of a C-based cell that *preserves the packet*
  (so that it can cross unboundedly many cells) would remove the transport
  asymmetry and make piles or a TM tape direct. The fuel-paying 8-A packet
  shows partial crossing is possible; the "same packet out" version is
  UNSAT for trains of width <= 24 (synth).
- A proof that no finite packet can relay (e.g. a charge or monotonicity
  invariant beyond width mod 14) would make the queue family (Q) the only
  option with stationary stores, and would be a result worth writing up by
  itself.
